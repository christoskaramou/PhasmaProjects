## Audit model

- IDs are stable, globally unique, lowercase keys. Category is presentation, not part of the key.
- Actor, effect, hazard, item, card, HUD, icon, font, and floor rows describe player-facing content.
- Scene rows describe authored defaults; runtime rows describe the scripts that may overwrite them.
- Generator and misc rows describe implementation dependencies, not additional visible objects.
- Blank asset/color/animation cells mean “not applicable,” not “unknown.”
- Unless listed below, a row is **verified** against the source commit above.

## Safe replacement workflow

1. Find the record. For active file-backed art, edit the selected runtime visual manifest; use
   `where`/`swap` for the consuming code and non-file visual properties.
2. Follow generator, authored-scene, emissive-slot, pooling, and animation dependencies below.
3. Run the relevant generator when the edited file is an input rather than a runtime asset.
4. Run `python tools/validate_visuals_db.py`.
5. Compare the Release-build captures required by `VISUAL_DIRECTION.md`.

## Cross-cutting constraints

This section contains only constraints that span multiple records. Row-specific details stay in the
tables above.

### Provenance and authority

- Lua asset paths normally resolve from `Assets/`: `Textures/...` and `Objects/...`.
- Scene texture paths resolve from `Assets/Scenes/`, so the same asset appears as
  `../Textures/...` in a scene and `Textures/...` in Lua.
- Inventory slot icon values omit `Textures/` (`ui/items/helmet.png`). Inventory passes them
  directly; beacon code prepends `Textures/`. Preserve both conventions.
- Authored scene values are initial state. HUD, hub, store, skills, settings, flow, and inventory
  scripts may rewrite color, text, visibility, or image data at runtime.
- `tools/build_scenes.py` owns generated UI nodes in `intro.pescene`, `hero_select.pescene`,
  and `game.pescene`. Edit generator constants and rerun it; direct edits to generated nodes are
  derived and may be overwritten.
- Per-mode actor art belongs in each mode's archetype/class data. Shared renderer helpers are
  plumbing unless a record explicitly identifies a global default.
- Monster rows inherit visual fields through `base`. Changing a base texture, sheet, projectile,
  tint, or extras changes every derived row that does not override it.
- Mode-select tile border, name, tagline, minimap, and position come from each `mode.lua` metadata
  table.
- Disabled screens and nodes remain in scope when reachable through a supported boot path. The
  side-select screen is reachable through `ATH_START=side`.
- `ATH_DEV=1` hitbox discs and diagnostic overlays are development records, not shipping art.

### Generated assets

Run generators with the Pillow-equipped `python` on this machine:

```text
python tools/gen_arena_creeps.py
python tools/gen_arena_heroes.py
python tools/gen_creep_sprites.py
python tools/gen_hero_sprites.py
python tools/build_scenes.py
```

- Generator paths are relative to each script; the working directory does not matter.
- Run `gen_arena_creeps.py` before `gen_creep_sprites.py`: beetle, corn-mortar, and wasp
  portraits are head-crop inputs for their sheets.
- Generated sheets use `phasma.sprite.v1`, 328x416 cells, five columns, pivot `[0.5, 0.85]`,
  and named clips.
- Hero and creep sheet generators assert the expected base frame count and clip boundaries. A frame
  layout change must update those assertions and metadata together.
- Spud portrait generators and arena sheet generators may use similarly named but different source
  PNGs. Keep full paths when reviewing or replacing them.
- Some bosses reuse a source head while their body is procedural:
  `gourd_king <- pumpkin_brute`, `wasp_queen <- wasp`, and
  `corn_colossus <- corn_mortar`.
- Generated hit flash and ground-shadow pixels are baked into sheets; runtime tint changes do not
  replace them.

### Materials and texture replacement

- Textured sprite quads use `alpha_cut`, double-sided rendering, and the same texture in base-color
  and emissive slots. Change both slots together.
- The white emissive factor is load-bearing on the self-lit stage. Base-slot-only replacements may
  appear dark or leave old art visible through emissive.
- Replacement PNGs need a clean alpha channel. Missing PNGs fall back to the archetype color
  silhouette; missing sheet metadata falls back to the static texture path.
- Creep emissive priority is: hit flash, fuse strobe, charge windup, dash, attack windup, then elite
  or archetype tint. Put persistent recolors in `stats.tint`; direct material writes are temporary.
- Status tint temporarily overrides base color and emissive, then restores the archetype tint.
- Elite gold is `View.ELITE_TINT`; elite scale is applied separately.
- Telegraph discs, bars, rings, arcs, mines, and blast decals require `alpha_blend` when their pool
  is created.
- `Art.tint` also reads `roughness` and `metallic` keys stored on its color table. A palette
  rewrite must preserve those material fields.

### Pooling, scale, and reuse

- Combat pools park nodes offstage instead of deleting them. Deletion can invalidate swap-and-pop
  draw constants.
- Per-spawn tint and texture writes overwrite pool-creation state. Apply archetype-specific visuals
  on every reuse.
- Sprite sheet bindings are cached by body node. A live art hot-swap must invalidate
  `D._topdown_dressed`; hero binding uses `D._topdown_hero_root/_topdown_hero_sheet`.
- Sprite size is creation-only: archetype scale, body scale, and top-down multipliers are baked when
  a rig is created. Position, rotation, and material remain safe live writes.
- Current melee reach and hero radius include transparent-padding assumptions. Art with different
  padding requires retuning the documented `0.35` and `0.55` factors.
- Node-adding `extras` run only for a fresh rig. Reused rigs receive per-spawn material/transform
  state, not new child nodes.
- Summoned or split archetypes must be prewarmed or their first rig is built during combat.

### Animation and effects

- Standard sprite sheets provide `idle`, `walk`, `attack`, `hit`, and `death`. Boss sheets
  also provide every named one-shot used by boss skills.
- Sprites are authored facing right; runtime mirrors left-facing movement with a 180-degree roll.
- Boss one-shots soft-fail when a clip is missing. Preserve clip names or update the corresponding
  `Anim.play_oneshot` call.
- `Art.SCALE` is the shared size control for text, UI, HUD, characters, effects, and camera zoom.
- Particle look is preset-driven. Bare `Art.burst` calls inherit the named preset; per-call colors
  apply only when explicitly supplied.
- Gold coin appearance has pool-build, respawn, and boss-skill restore writes. Keep those values
  synchronized until a shared token replaces them.
- `Art.SHAKE_ENABLED` is currently false. Visual feedback must remain understandable without
  camera shake.

### UI and text

- `Art.quad` is the runtime UI choke point for flat color, borders, text, images, and image tint.
- UI geometry uses raw surface pixels while the backend applies DPI scaling to fonts. Change
  `Art.SCALE.text`, not per-call DPI compensation.
- The runtime atlas loads Latin and Greek glyph ranges. `Art.ascii` downmaps unsupported
  typographic symbols such as arrows, stars, bullets, and curly quotes.
- Centering helpers and some legacy labels use hand-tuned glyph-width/top-anchor compensation.
  Recheck them after any font or font-scale change.
- Text-style widgets cannot draw an image; inventory icons are separate image quads over their text
  tiles.
- Transient inventory overlay IDs are contractual because clear paths remove them by exact string.
- Letterboxing is fixed at 20:9. Letterbox quads compensate for the viewport offset and must retain
  that coordinate treatment.
- The world map draws full-bleed, outside the 20:9 band. Replacing `worldmap.png` requires
  reauthoring all station and route coordinates.
- The UI currently has duplicated palette literals. Consolidate only shared semantic tokens
  (background, border, selection, danger, rarity); do not introduce a 473-entry runtime registry.
